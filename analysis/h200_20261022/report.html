Recommended next-run experiments

1. Standardize GPU topology

Prefer GPU pairs with confirmed NVLink connectivity. π0.5-KR and SmolVLA-KR currently show NODE paths and H200 NVL devices; other running pairs show NV18. π0.5-KR averages 14.6/14.2 GB/s PCIe receive/transmit in this short sample. Communication is a strong suspect, not a proven isolated bottleneck. Match hardware before attributing timing differences to KR.

2. Reduce gradient accumulation where memory permits

VLASH: try microbatch 16 × 2 GPUs × accumulation 1, keeping global batch 32 (currently 8 × 2 × 2). DOM: try 44 × 2 × 4, then 88 × 2 × 2; both preserve global batch 352 (currently 22 × 2 × 8). These are candidates, not measured speedups. DOM may contain batch-dependent layers, so changing microbatch can change behavior even with fixed global batch.

3. Use SmolVLA GPUs more economically

Try one GPU, microbatch 64, accumulation 1, global batch 64, against the current two-GPU setup. Low memory consumption alone does not prove low computational utilization: live GPU busy time is 89–95%. Measure both samples/s and samples per GPU-second. Larger global batches 128/256 are separate optimization experiments that change training statistics and scheduling.

4. Trade memory for recomputation on π0.5

At fixed global batch 32, the current microbatch 16 already requires no accumulation. Benchmark gradient checkpointing off, keeping precision fixed, since the observed peak is ~59 GiB. Fit is not guaranteed. Retain BF16 autocast; do not switch to pure FP32 compute. Precision storage changes are a separate numerical experiment.

5. Tune data loading and CPU placement

Sweep 4/8/12 workers per rank and prefetch 2/4 within the 32-CPU allocation, recording loader wait time and host memory. Saved CPU measurements are rank-0 process-tree averages across readiness, not whole-job production CPU utilization. π0.5/VLASH preparation currently synchronizes GPU state to CPU for state tokenization; moving equivalent work to CPU preprocessing is worth profiling. DOM uses blocking tensor transfers despite pinned loaders; consider nonblocking transfers after measuring copy overlap.

6. Measure optimizer and orchestration overhead

π0.5 already uses fused AdamW; other families do not. Benchmark fused AdamW separately for SmolVLA, VLASH and DOM. DDP already uses no_sync for intermediate accumulation steps and gradient bucket views. Do not simply disable find_unused_parameters: unused parameter handling must be established first. Compilation is disabled for cross-VLA models; consider it only after higher-priority changes, including compile/startup costs.

7. Protect continuation and report comparable rates

π0.5 baseline was preempted and pending at the snapshot. Retain requeue/resume and consider a shorter checkpoint interval if preemptions are frequent, balancing write cost. Preserve horizon 20, data split, LR schedule and effective batch for hardware comparisons. Add representative step timing, data wait, HBM/NVLink counters, and disk throughput before declaring bandwidth saturation.

Recommendations have not been benchmarked. Existing readiness checks were inspected; no new tests or training jobs were launched. Short monitoring steps ran inside existing allocations.
